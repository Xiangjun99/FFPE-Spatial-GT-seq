# FFPE Spatial-GT-seq ADT Preprocessing

This directory contains the preprocessing workflow for **Antibody-Derived Tag (ADT) sequencing data generated by FFPE spatial-GT-seq**.

The pipeline uses **Snakemake** to:

1. filter reads according to the expected primer and linker sequences,
2. extract and reconstruct the spatial barcode and UMI from Read 2,
3. match spatial barcodes against a predefined 72 × 72 barcode whitelist, and
4. quantify antibody-derived tags using **CITE-seq-Count**.

## Directory contents

```text
spatial FFPE-GT-seq ADT/
├── Snakefile
├── fastq_process.py
├── WHITELIST_ADT_72x72.csv
└── TAG_LIST_Hu154.csv
```

### `Snakefile`

Main Snakemake workflow controlling the complete ADT preprocessing pipeline.

The workflow consists of four major processing stages:

```text
Raw paired-end FASTQ
        |
        v
Primer filtering
        |
        v
Linker 1 filtering
        |
        v
Linker 2 filtering
        |
        v
Spatial barcode + UMI reconstruction
        |
        v
CITE-seq-Count
        |
        v
ADT count matrix
```

### `fastq_process.py`

Processes the filtered Read 2 FASTQ file and reconstructs the sequence required for ADT counting.

The processed read contains:

```text
BC2 + BC1 + UMI
```

The final processed sequence is:

```python
new_seq = seq[32:40] + seq[70:78] + seq[22:32]
```

Therefore, the reconstructed read has the following structure:

```text
|------ 16-bp spatial barcode ------|---- 10-bp UMI ----|
|       BC2       |       BC1       |       UMI         |
|      8 bp       |      8 bp       |      10 bp        |
```

The corresponding FASTQ quality scores are rearranged in the same order.

Usage:

```bash
python fastq_process.py \
    --input input_R2.fastq.gz \
    --output output_R2.fastq.gz
```

### `WHITELIST_ADT_72x72.csv`

Whitelist containing valid spatial barcodes for the **72 × 72 spatial array**.

The file contains:

```text
72 × 72 = 5,184 spatial barcodes
```

Each spatial barcode is 16 bp long and corresponds to the concatenation:

```text
BC2 + BC1
```

For example:

```text
AACGTGATAACGTGAT
AACGTGATGCGAGTAA
AACGTGATATGCCTAA
...
```

This whitelist is supplied to `CITE-seq-Count` through the `-wl` option and is used to restrict barcode assignment to valid spatial positions.

### `TAG_LIST_Hu154.csv`

Reference file used by `CITE-seq-Count` to assign ADT reads to antibody targets.

Each row contains:

```text
<ADT barcode>,<target name>
```

For example:

```text
GTCTTTGTCAGTGCA,CD86
GTTGTCCGACAATAC,CD274
TGATAGAAACAGACC,TNFRSF14
ATCACATCGTTGCCA,PVR
AACCTTCCGTCTAAG,NECTIN2
```

The reference includes antibody targets as well as control antibodies such as mouse and rat IgG isotype controls.

This file is passed to `CITE-seq-Count` using the `-t` option.

## Workflow

### 1. Input FASTQ detection

Samples are detected automatically from subdirectories under `rawData_dir`.

For example:

```text
raw_data/
├── sample1/
│   ├── sample1_1.fastq.gz
│   └── sample1_2.fastq.gz
├── sample2/
│   ├── sample2_1.fastq.gz
│   └── sample2_2.fastq.gz
└── ...
```

Each subdirectory is treated as one sample.

---

## 2. Primer filtering

The first filtering step uses `bbduk.sh` to retain read pairs containing the expected primer sequence:

```text
CAAGCGTTGGCTTCTCGCATCT
```

Outputs:

```text
<sample>_R1_filtered_primer.fastq.gz
<sample>_R2_filtered_primer.fastq.gz
```

Filtering statistics are saved to:

```text
<sample>_stats.primer.txt
```

---

## 3. Linker 1 filtering

Primer-filtered reads are further filtered for Linker 1:

```text
GTGGCCGATGTTTCGCATCGGCGTACGACT
```

Outputs:

```text
<sample>_R1_filtered_linker1.fastq.gz
<sample>_R2_filtered_linker1.fastq.gz
```

Filtering statistics are written to:

```text
<sample>_stats.linker1.txt
```

---

## 4. Linker 2 filtering

Reads passing the Linker 1 step are filtered for Linker 2:

```text
ATCCACGTGCTTGAGAGGCCAGAGCATTCG
```

The resulting files are:

```text
<sample>_R1.fastq.gz
<sample>_R2_filtered_linker2.fastq.gz
```

Filtering statistics are written to:

```text
<sample>_stats.linker2.txt
```

---

## 5. Spatial barcode and UMI reconstruction

The filtered Read 2 FASTQ file is processed using:

```bash
python fastq_process.py \
    --input <sample>_R2_filtered_linker2.fastq.gz \
    --output <sample>_R2.fastq.gz
```

The script extracts three sequence segments from the original R2:

```text
Original R2
    |
    |-- bases 23–32 --> UMI  (10 bp)
    |
    |-- bases 33–40 --> BC2  (8 bp)
    |
    |-- bases 71–78 --> BC1  (8 bp)
```

These segments are rearranged into:

```text
Processed R2
┌───────────────┬───────────┐
│ Spatial BC    │    UMI    │
│   16 bp       │   10 bp   │
├───────┬───────┼───────────┤
│  BC2  │  BC1  │    UMI    │
│ 8 bp  │ 8 bp  │   10 bp   │
└───────┴───────┴───────────┘

        BC2 + BC1 + UMI
```

The resulting processed R2 is therefore **26 bp** long.

---

## 6. ADT counting with CITE-seq-Count

The processed reads are quantified using `CITE-seq-Count`.

The workflow uses:

```bash
CITE-seq-Count \
    -R1 <sample>_R2.fastq.gz \
    -R2 <sample>_R1.fastq.gz \
    -t TAG_LIST_Hu154.csv \
    -trim 21 \
    -cbf 1 \
    -cbl 16 \
    -umif 17 \
    -umil 26 \
    -cells 2500 \
    -wl WHITELIST_ADT_72x72.csv \
    -T 20 \
    -o <output_directory>
```

### Barcode configuration

The reconstructed R2 has the structure:

```text
Positions:   1               16 17              26
             |----------------| |----------------|
             Spatial barcode         UMI
                 16 bp               10 bp
```

# Requirements

The pipeline requires:

* Python 3
* Snakemake
* Biopython
* BBMap (`bbduk.sh`)
* CITE-seq-Count

Python dependencies can be installed, for example, using:

```bash
pip install biopython snakemake CITE-seq-Count
```

BBMap can be installed separately or through Conda.

---

# Configuration

Before running the workflow, modify the paths at the beginning of the `Snakefile` according to the local computing environment.

The current configuration contains:

```python
rawData_dir = "/path/to/raw/ADT/data"
processedData_dir = "/path/to/processed/ADT/data"

fastq_ext = ".fastq.gz"

core = 20

bbduk_dir = "/path/to/bbduk.sh"

whitelist = "WHITELIST_ADT_72x72.csv"
ref_dir = "TAG_LIST_Hu154.csv"
```

`rawData_dir`, `processedData_dir`, and `bbduk_dir` should be changed before running the workflow on another system.

The following files should be available from the working directory:

```text
fastq_process.py
WHITELIST_ADT_72x72.csv
TAG_LIST_Hu154.csv
```

---

# Running the pipeline

Run the complete workflow with:

```bash
snakemake -s Snakefile --cores 20
```

To inspect the planned jobs without executing them:

```bash
snakemake -s Snakefile -n
```

# Summary

The spatial FFPE-GT-seq ADT preprocessing workflow converts raw paired-end sequencing reads into spatially resolved ADT counts using the following strategy:

```text
Raw FASTQ
   |
   v
Primer filtering
   |
   v
Linker 1 filtering
   |
   v
Linker 2 filtering
   |
   +------------------------------+
   |                              |
   v                              v
Filtered original R1       Filtered original R2
ADT sequence                       |
                                   v
                           fastq_process.py
                                   |
                                   v
                         BC2 + BC1 + UMI
                         16 bp    + 10 bp
   |                              |
   +---------------+--------------+
                   |
                   v
             CITE-seq-Count
                   |
          +--------+--------+
          |                 |
          v                 v
  72 × 72 spatial       ADT barcode
  barcode whitelist     reference
          |                 |
          +--------+--------+
                   |
                   v
          Spatial ADT counts
```
