# Single-cell DNA-seq Preprocessing

This directory contains the preprocessing workflow used to generate individual single-cell BAM files from single-cell whole-genome sequencing data for downstream copy-number variation (CNV) and coverage-based analyses.

Single-cell DNA sequencing data were initially processed using the **Cell Ranger DNA v1.1 CNV pipeline** and aligned to the mouse reference genome (**mm10**). The resulting position-sorted BAM file was subsequently split into individual single-cell BAM files based on the cell barcode stored in the BAM `CB` tag.

Each per-cell BAM file was coordinate-sorted and indexed using **SAMtools v1.21**.

---

## Workflow overview

```text
Raw single-cell DNA sequencing data
                |
                v
        Cell Ranger DNA v1.1
                |
                v
        Alignment to mm10
                |
                v
        possorted_bam.bam
                |
                v
     Cell barcode list
                |
                v
Extract reads using BAM CB tag
                |
                v
      One BAM per cell
                |
                v
        SAMtools sort
                |
                v
        SAMtools index
                |
                v
 Sorted + indexed single-cell BAMs
                |
                v
       Downstream CNV analysis
```

## Input

### Position-sorted BAM

The main input is the position-sorted BAM file generated by Cell Ranger DNA:

```text
possorted_bam.bam
```

This BAM file contains reads from all detected cells.

Cell identity is stored in the BAM file using the `CB` tag.

A typical tagged alignment therefore contains a field conceptually similar to:

```text
CB:Z:<cell_barcode>
```

The workflow uses this barcode tag to extract reads belonging to each individual cell.

---

## Cell barcode list

A text file containing valid cell barcodes is used to determine which cells should be extracted from the pooled BAM file.

Example:

```text
valid_barcodes_no_prefix1.txt
```

The file contains one cell barcode per line.

For example:

```text
ATTACTCCAGTCAGCC-1
TTAGCGAGTGGTAAGC-1
AGTTACGGTACCCATA-1
CGTTCCACACCCATCT-1
CAGCTGGGTTAGGAAT-1
```

Each barcode corresponds to one individual cell.

The barcode strings must match the values stored in the BAM `CB` tag.

---

## Reference genome

Species:

```text
Mus musculus
```

Reference genome:

```text
mm10
```

The initial alignment was performed as part of the Cell Ranger DNA v1.1 CNV workflow.

For full reproducibility, the exact Cell Ranger DNA reference package used for the original alignment should be retained or documented when available.

---

## Splitting the BAM file by cell barcode

Reads were extracted from the pooled Cell Ranger DNA BAM file using the `CB` auxiliary tag.

For a given barcode:

```bash
BC=<cell_barcode>
```

reads corresponding to that cell were extracted using:

```bash
samtools view \
    -b \
    -d CB:$BC \
    possorted_bam.bam
```

The `-d` option filters BAM records according to the specified auxiliary tag.

In this workflow:

```text
CB:<barcode>
```

is used to select reads belonging to an individual cell.

---

## Sorting individual-cell BAM files

The extracted reads are piped directly into `samtools sort`.

The command used is:

```bash
samtools view -b -d CB:$BC $BAM \
    | samtools sort \
        -@ 2 \
        -o $OUTDIR/${BC}.sorted.bam
```

This avoids generating an intermediate unsorted BAM file.

For example:

```text
ATTACTCCAGTCAGCC-1
```

produces:

```text
ATTACTCCAGTCAGCC-1.sorted.bam
```

---

## BAM indexing

Each sorted single-cell BAM file is indexed using:

```bash
samtools index $OUTDIR/${BC}.sorted.bam
```

This generates:

```text
ATTACTCCAGTCAGCC-1.sorted.bam
ATTACTCCAGTCAGCC-1.sorted.bam.bai
```

The BAM index allows efficient retrieval of reads from specific genomic regions during downstream analysis.

---

## SLURM array processing

The per-cell BAM generation was parallelized using a SLURM job array.

For each SLURM array task, one barcode is selected from the barcode list using:

```bash
BC=$(sed -n "${SLURM_ARRAY_TASK_ID}p" $BARCODES)
```

Therefore:

```text
SLURM_ARRAY_TASK_ID=1
```

uses the first barcode in the barcode file,

```text
SLURM_ARRAY_TASK_ID=2
```

uses the second barcode,

and so on.

Conceptually:

```text
Barcode list
    |
    +-- line 1 -> SLURM task 1 -> Cell 1 BAM
    |
    +-- line 2 -> SLURM task 2 -> Cell 2 BAM
    |
    +-- line 3 -> SLURM task 3 -> Cell 3 BAM
    |
    +-- ...
```

This allows thousands of single cells to be processed independently and in parallel on an HPC cluster.

The SLURM array range should match the number of barcodes in the barcode file.

For example, if the file contains 7,234 barcodes:

```bash
#SBATCH --array=1-7234
```

## Example splitting script

A simplified version of the workflow is:

```bash
BAM="/path/to/possorted_bam.bam"
BARCODES="/path/to/valid_barcodes_no_prefix1.txt"
OUTDIR="/path/to/per_cell_bam"

mkdir -p "$OUTDIR"

# Obtain the barcode corresponding to the current SLURM array task
BC=$(sed -n "${SLURM_ARRAY_TASK_ID}p" "$BARCODES")

echo "Processing barcode $BC"

# Extract reads for one cell and coordinate-sort the BAM
samtools view -b -d CB:$BC "$BAM" \
    | samtools sort \
        -@ 2 \
        -o "$OUTDIR/${BC}.sorted.bam"

# Generate BAM index
samtools index "$OUTDIR/${BC}.sorted.bam"

echo "Finished barcode $BC"
```

Cluster-specific absolute paths should be replaced before running the workflow on another system.

## Output

The final output directory contains one sorted and indexed BAM file for each cell barcode.

For example:

```text
per_cell_bam/
├── ATTACTCCAGTCAGCC-1.sorted.bam
├── ATTACTCCAGTCAGCC-1.sorted.bam.bai
├── TTAGCGAGTGGTAAGC-1.sorted.bam
├── TTAGCGAGTGGTAAGC-1.sorted.bam.bai
├── AGTTACGGTACCCATA-1.sorted.bam
├── AGTTACGGTACCCATA-1.sorted.bam.bai
└── ...
```

Each BAM file contains reads assigned to one individual cell according to the `CB` tag.

## Software

The preprocessing workflow used:

| Software        |           Version | Purpose                                                  |
| --------------- | ----------------: | -------------------------------------------------------- |
| Cell Ranger DNA |               1.1 | Initial scDNA-seq processing and alignment               |
| SAMtools        |              1.21 | Cell-specific read extraction, BAM sorting, and indexing |
| SLURM           | cluster dependent | Parallel processing of individual cell barcodes          |

The SAMtools version can be checked using:

```bash
samtools --version
```

The version used for this analysis was:

```text
samtools 1.21
```

## Downstream analysis

The resulting sorted and indexed single-cell BAM files can be used for downstream analyses such as:

* single-cell copy-number variation analysis
* read-depth analysis
* genome-wide coverage analysis
* chromosome-level coverage analysis
* comparison of CNV profiles across individual cells

Because each BAM corresponds to one cell, genomic coverage and copy-number profiles can be calculated independently for each cell.

## Reproducibility

The key parameters required to reproduce the single-cell BAM generation are:

```text
Cell Ranger DNA version: 1.1
Reference genome: mm10
Cell barcode BAM tag: CB
SAMtools version: 1.21
Sorting threads per cell: 2
Barcode list: valid_barcodes_no_prefix1.txt
```

The essential extraction command is:

```bash
samtools view -b -d CB:$BC possorted_bam.bam \
    | samtools sort -@ 2 -o ${BC}.sorted.bam

samtools index ${BC}.sorted.bam
```

The same barcode list, Cell Ranger DNA output BAM, reference genome, and software versions should be used when reproducing the original analysis.
